# 边界与状态契约

## 用变化检验边界

选择确有意义的变化追踪调用和依赖：修改 UI、替换 Provider、改变缓存、增加平台、更换业务规则。检查是否局限于预期职责，是否存在复制规则或跨层泄漏。新平台可复用规则与契约，调度、渲染、凭据与生命周期通常仍需适配。

契约由稳定策略一侧拥有；实现位于外层。共享模块不是垃圾桶。允许适当领域库依赖，但检查是否引入 I/O、平台耦合或不可控时间。注入时钟、身份与必要上下文，不依赖系统全局对象。使用不可变值或受控可变状态，不为形式完整复制每层模型。

## 外部模型归一化

传输对象转成领域数据时，验证单位、范围、缺失值、时区、身份与稳定标识。区分解析失败、未知值、无权限、网络失败、旧缓存与真实零值。Provider 解释协议字段，Domain 决定业务意义，Presentation 决定提示文案。

错误按需携带类别、可重试性与脱敏诊断信息；领域契约不绑定 HTTP 状态或 Toast。未经验证的部分响应不得覆盖完整有效状态；允许部分结果时明确有效字段及来源。

## 共享异步状态

只在存在共享状态时采用以下约束，无状态脚本无需快照系统。

- 每个一致性范围指定权威状态所有者与唯一提交路径；UI 可保有短期交互状态。
- 快照或等效机制保留必要的身份、修订号、采集时间、来源与新鲜度，不强求全局对象承载所有领域。
- 规定成功、失败、刷新中、离线、登录过期的状态转移；旧数据可保留，不能标成刚刚刷新成功。
- 乱序结果使用序列、会话 epoch 或等效提交前提。取消网络请求不足以阻止迟到回调提交。
- 账户切换、退出与重登隔离身份和会话，检查凭据与缓存归属，防止 A 的结果写入 B。
- 领域时间判断与系统任务执行分离；提醒去重使用稳定事件或周期身份，不依赖显示文本或数组位置。
- 原子提交一致数据，再驱动表面刷新；平台发布失败不能静默改写领域查询结果。
- 明确一致性级别和允许延迟。Widget 与通知未必同时绘制，但应可追溯消费的状态版本。

## 平台与展示

生命周期、权限、后台限制、任务恢复和发布 API 属于平台接入。业务判断是否需要提醒，平台判断能否执行并反馈结果。展示格式化可以共用，不掺入网络解析或状态提交规则。

主题、布局与动效属于展示约束，迁移应保护已有体验。跨语言共享规格、测试向量或协议；验证是否值得共享二进制，避免为复用强引入 FFI 或服务化。
