# 验收与交付

## 最小证据表

优先使用工程已有记录，建立主张与证据对应：

| 主张 | 合适证据 | 不足以单独证明 |
|---|---|---|
| 核心独立于平台 | 依赖检查、独立构建或测试、外部调用审阅 | 名为 core 的目录 |
| 规则有唯一权威实现 | 调用和写入路径、旁路删除、行为验证 | 接口已建立 |
| 账户与并发安全 | 控制回调顺序、切换身份、检查提交与发布 | 一次正常查询 |
| 表面状态一致 | 同修订输入及结果核对、实际刷新路径 | 截图数字偶然相同 |
| 升级保留数据 | 旧样本升级、配置核对、安装身份核验 | 新装正常 |
| 体验未退步 | 受影响渲染与交互检查 | 编译成功 |

记录命令、环境、内容标识、观察、失败与限制。验证只属于被测内容，相关代码再改后重跑对应检查。搜索适合发现线索，结论需核对实际依赖与路径。

## 按风险选场景

共享异步状态：正常成功、失败保留旧数据、乱序、退出后迟到、切换账户、同身份重登、取消、缓存归属、部分响应、过期数据与发布失败。通过可控 fake、时钟或集成复现机制，不只检查方法存在。

持久化变化：旧格式、缺失字段、损坏数据、中断与恢复。时间规则：边界、时区或周期。平台变化：权限、后台限制、进程恢复和目标环境。只选受影响场景，不给低风险文案修改强加全套测试。

复用依赖分析或 lint；必要时建立小范围约束并证明其能发现违规。不用通用 regex 宣称跨语言依赖分析。结构测试防回归，行为测试确认语义。

## 结论与交付

保留用户实机反馈并注明版本与已知路径，未知覆盖不补造。模拟器不等于 OEM 真机，mock 不等于真实服务，单测不等于升级成功。

按范围和环境限定结论：结构验证通过、行为回归通过、目标环境待验收或部分阻塞。无源码证据不宣布架构完成；无实际产物与成功构建不宣布可运行版本。

交付先说明结果与影响，再列证据和未验证项。留下依赖方向、状态所有者、临时例外与下一触发条件。用户要求可分发模板时再建模板，技能正文不是运行框架。
